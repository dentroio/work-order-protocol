# Evangelism Plan

Work Orders need to be explained as a practical answer to a real problem:
software teams now have powerful coding agents, but most work artifacts were not
designed for cold-start implementation.

## Core Message

> Tickets identify work. Work Orders make work executable.

## Audience

- engineering leaders adopting coding agents
- senior engineers tired of vague tickets
- developer productivity teams
- startup founders using AI coding tools
- open-source maintainers receiving AI-generated pull requests

## Positioning

Work Order Protocol is not another project management app. It is a lightweight
specification and delivery discipline that works with the tools teams already
use.

## Blog Series

1. **Tickets Are Not Enough For Coding Agents**
   - Problem: tickets rely on shared context.
   - Thesis: coding agents need dispatchable work.

2. **The Cold Start Test**

3. **A Work Order Is A Contract, Not A Prompt**

4. **How To Add Work Orders To Any Repo In One Afternoon**

5. **Risk Tiers Are An Autonomy Budget**
   - P0-P3.
   - When humans must verify.

6. **From Work Orders To Agentic Factories**
   - Optional automation path.
   - Queueing and dashboards come after the protocol.
